# HUMAN_REPORTING — 人間向け報告の固定ルール

Aeterna の自動研究では、**科学的な記録**と**人間が最初に読む説明**を分ける。

目的は、研究内容を簡略化して証拠を捨てることではない。内部の識別名・数値・測定値・計算設定はすべて従来どおり保存したまま、最初に読む報告だけを「研究の意味が分かる順番」に変える。

## 最初に必ず答えること

人間向け報告は、必ず次の順番にする。

1. **要するに、目的地はどこか**
2. **現在地はどこか**
3. **今回できたこと**
4. **まだできていないこと**
5. **次に確かめること**

「何回試したか」「内部で何という候補名か」より前に、まずこの五つを伝える。

## 最初の説明に出さないもの

初見の理解に不要な次の情報は、第一層の説明へそのまま出さない。

- 内部の候補識別名
- 実験の通し番号
- 変数名
- 英語の状態名や略語
- 生の評価値
- 細かな実験回数
- 数値レギュレータ
- 人間が先に決めた参照段階のコード名

必要な情報を隠蔽するのではなく、**機械向け記録・技術記録へ残す**。

## 数字の扱い

第一層では、数字そのものが研究の意味でない限り出さない。

たとえば「二千回以上試した」は、研究の現在地を理解するための第一情報ではない。まず「条件を広く変えて調べた」「似た変化が別条件でも現れた」のように意味を伝える。

正確な回数は技術記録で確認できるようにする。

## 科学的な慎重さは簡略化しない

分かりやすくするために、次の区別を消してはいけない。

- 観測したこと
- 解釈していること
- まだ確かめられていないこと
- 反証の余地

したがって、人間向け報告にも「まだできていないこと」を必須項目として置く。

## 実装

`ai_lab/dream/human_report.py` が人間向け要約を生成する。

- 夜間報告の標準 Markdown は人間向け要約を表示する。
- 詳細な技術 Markdown と JSON は別に保存する。
- Easy Report も最終的に同じ人間向け要約へ変換する。
- Observatory では目的地・現在地・今回できたことを最初に表示し、内部記録は折りたたむ。
- CI は第一層に生の識別名、英語の内部用語、数字が漏れないことを検査する。

この報告層は、実験結果・科学判定・公式段階・Room 昇格条件を変更しない。
