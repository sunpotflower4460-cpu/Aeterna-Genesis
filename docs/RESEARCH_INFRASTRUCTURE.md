# Aeterna Research Infrastructure Contract

This document defines the operational contract that lets autonomous research expand without turning
planning convenience into scientific evidence.

The short version is:

> **Explore broadly, remember exactly what was tested, preserve negative evidence, add instruments before
> adding claims, and make every burst auditable after the fact.**

This infrastructure is not a new physics model.  It must never change a scientific result merely because
that result is inconvenient, repetitive, negative, low-gain, or hard to interpret.

## 1. Evidence layers and authority

Aeterna deliberately separates several layers that are easy to conflate.

1. **Scientific evidence** — simulation outputs, measured observables, start-purity records, Prefix
   Identity audits, Cross-World primary/shadow reports, Deep-Time records, open-ended transition ledgers.
2. **Planning state** — frontier allocation, Progress Ratchet question memory, hypothesis portfolio,
   operational/instrument backlog.  These choose what to inspect next; they are not physical observables.
3. **Human views** — Easy reports, Research Compass and Markdown summaries.  These improve orientation but
   never override the raw evidence.
4. **Infrastructure health** — consistency checks for stale aliases, broken memory contracts, impossible
   accounting, NØ drift, or shadow layers that accidentally promote claims.
5. **Immutable provenance manifest** — SHA-256 identities of the files that constituted a completed burst.
   A hash proves byte identity, not scientific validity.

If two layers disagree about scientific content, the raw scientific evidence remains authoritative and the
view/planning layer must be fixed.

## 2. Productive autonomy means information gain, not success chasing

The autonomous router may prefer experiments that are more falsifiable or that cover a genuinely new
condition.  It may rotate away from a saturated lead.  It may reserve a small control lane for an old
question.  None of those planning choices can relax a scientific threshold or promote a Room/official
Emergence Level.

A burst is allowed to produce:

- no new phenomenon,
- a negative intervention,
- a failed replication,
- a weakened X candidate,
- no Cross-World match,
- no F-path advance,
- a stable long-lived state that does not progress further.

Those are scientific outcomes, not infrastructure failures.

Infrastructure should fail closed only when the *research machinery* becomes untrustworthy: stale evidence
is presented as current, durable memory is corrupted, accounting is impossible, an immutable archive would
be silently rewritten, or a shadow observer gains promotion authority.

## 3. Question identity must describe the question that was actually asked

For mutable X search focuses, `X-ID + varied knob + value` is not enough.  The same fingerprint can later be
selected from another start-side condition.

Context-aware X question identity therefore uses:

- X pattern ID,
- start family,
- every clipped **pre-intervention** base knob,
- the varied knob,
- the post-clipping value that actually executed.

It must not use:

- whether the X was observed,
- episode outcome,
- target morphology,
- vortex/triangle/split result,
- local energy result,
- any post-run measurement.

This keeps the memory useful without encoding the desired answer.  Historical contextless keys remain
preserved as history, but ambiguous old coverage must not suppress a materially new start context.

## 4. Durable memory and route escape

Research Memory is append-preserving.  A completed question should not become "new" merely because a short
ledger window rolled over.  Reporting layers must preserve document-level schema/count/policy metadata as
well as the entries themselves.

A low-gain or replication-only burst may request a route change for the next burst.  That escape is a
planning instruction, not evidence against the phenomenon.  Context-aware X escape should block the same
start context, not every future occurrence of the same fingerprint under all conditions.

## 5. Instruments before claims

When a desired capability cannot yet be measured, the correct next step is normally an instrument, not a
more ambitious interpretation.

The current frontier can request instruments such as:

- metric-from-relations,
- identity-continuity,
- damage-recovery,
- growth-accounting,
- predictive-holdout,
- lineage-accounting.

These requests are preserved in a durable operations backlog because a burst-local report may stop showing
one even though the measurement gap still exists.

**An instrument request is not evidence that the requested phenomenon exists.**

Some instruments may use a parallel scaffolded analogy lane.  Such a lane must remain labelled and cannot
count as Pure Genesis proof.  In particular, scaffolded/correlated starts are not described as strict
"from nothing" evidence.

## 6. NØ remains a null control

Strict NØ contains no physical entity, state, transition law, time, randomness, geometry or possibility
space.  It therefore has no physical next-state calculation to repeat across seeds.

Infrastructure may verify that the NØ report remains a single declarative null control.  It must not turn
constructor behavior into a passed independent emergence audit.  The eighth-audit verdict remains
`DECLARATIVE_NULL_CONTROL_NOT_A_PASSED_EIGHTH_AUDIT` unless the experiment itself is explicitly redesigned
outside strict NØ.

## 7. Cross-World and Multi-World are shadows

Cross-World fingerprint overlap and independent fresh-seed replication are useful navigation evidence.
They do not establish identical physics or universality.  Multi-World and Cross-World observers must not:

- update Room promotion,
- change official Emergence Levels,
- change hypothesis confidence directly,
- mutate world dynamics,
- treat a matching fingerprint as a conserved quantity, defect, force, or common law.

An interrupted/non-finite replication is instrumentation status, not a physical miss.

## 8. F0–F7 remains one reference route

F0–F7 is a human-written relation-fission reference path, not the natural route assumed by the autonomous
researcher and not the official Emergence Levels.

The router may continue to falsify or compare this route, but depth alone cannot get first refusal on
compute.  Deep-Time raw F-depth changes also require Prefix Identity / historical semantics audits before
being interpreted as physical regression.

## 9. Local Vortex Energy remains measurement-after-selection

Geometry selects a vortex relation first; energy is measured afterward.  The infrastructure may preserve
and compare these measurements, but a local GL-energy contrast is not automatically a binding energy,
effective force or causal mechanism.  A causal interpretation requires a separate perturbation/integrity
study.

## 10. Postflight pipeline

After a successful `Genesis Dream Loop` has persisted its evidence to `main`, the Research Postflight
Integrity workflow runs on the actually committed final burst:

1. audit Research Health,
2. preserve the durable instrument/infrastructure backlog,
3. create or verify the immutable per-burst provenance manifest,
4. upload diagnostic artifacts,
5. commit healthy postflight records with rebase/retry protection,
6. fail closed if strict infrastructure errors exist.

Postflight intentionally does **not** rerun Research Compass.  Re-running a memory-merging human view in a
second workflow would make report generation itself affect observation counters.

A safety-net workflow that observes an already-manifested burst verifies the archive instead of silently
rewriting it.

## 11. Per-burst provenance manifest

Each completed burst can have:

`ai_lab/reports/easy/manifests/<burst-id>.json`

The manifest separates scientific evidence, planning/integrity state, and derived human views.  It records
SHA-256 hashes plus the research workflow/source identity that produced the burst.

Rules:

- the same archive may be re-read or verified,
- identical idempotent creation is allowed,
- different provenance under the same burst ID is an error,
- the archive is never silently overwritten,
- a file hash is not scientific validation,
- negative evidence is intentionally included rather than filtered away.

## 12. How future agents should extend Aeterna

Before adding an autonomous research capability, use this checklist:

1. State the scientific question and the claim boundary.
2. Identify which givens are already supplied by the model.
3. Add a read-only instrument before adding an interpretation when the quantity is currently unmeasured.
4. Keep intervention identity start-side and independent of the desired outcome.
5. Add fresh-seed controls / contrasts / ablations appropriate to the question.
6. Preserve numerical failures as numerical/instrumentation status, not physical negative evidence.
7. Persist completed-question identity if exact repetition can waste future compute.
8. Add the new durable file to provenance categories if it affects scientific evidence, planning, or views.
9. Add an infrastructure-health check if silent corruption or stale reuse would be dangerous.
10. Add regression tests and wire those tests into CI explicitly.
11. Keep scaffolded analogy lanes labelled and outside Pure Genesis proof.
12. Never let an orientation score, backlog priority, progress score, health score or hash promote a
    scientific claim.

## 13. What this infrastructure cannot guarantee

No scheduler or optimizer can guarantee that every burst discovers a new natural phenomenon.  What it can
guarantee much more reliably is that compute is less often spent on accidental duplicates, measurement
gaps are not forgotten, negative evidence is retained, stale reports are detected, and a future researcher
can reconstruct what the system believed it had actually tested.

That is the intended meaning of "productive autonomous expansion" in Aeterna.
