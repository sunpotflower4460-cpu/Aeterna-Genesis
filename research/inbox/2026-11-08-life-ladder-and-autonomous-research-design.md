- 対象：Aeterna-Genesis
- 状態：**下書き**（2026-11-08、人と AI の対話から起草。未決の箇所は §5）
- 位置づけ：北極星と既存の「はしご」（P14〜P19）、RESEARCH_COMPASS の開いている問い、LAW.md（7＋8監査・役割 E/V/S/N/F/Q・claim tier）の枠組みの中で読む文書。既存の掟・羅針盤・天井地図を変更しない。

## 第1部 生命のはしご（光 → 流れ → 器 → 成長 → 分裂 → 遺伝の入口）

### 0. 大原則

- 各段は独立に監査できる単位に切る。段を飛ばして上の主張をしない。
- 「割れろ」「袋になれ」と結果を名指しする規則・初期条件・評価ゲートは置かない（第8監査：結論と同型の因果の埋め込み禁止）。
- 光の役割は3つに仕分けし、混ぜない：
  - **エネルギー源**（低エントロピーの流れ）… 熱力学として established
  - **勾配と時計**（膜内外の差、昼夜の周期強制）… observed〜interpretive
  - **経路和との構造的類似** … analogy のみ。生命の主張の根拠には使わない

### 段 L0：非平衡の流れ（土台）

- 問い：一定のエネルギー流入のもとで、散逸構造（対流ロール等）は統計的に持続するか。
- 入れるもの：既存の白（Boussinesq 対流など、法則 A）の駆動条件のみ。
- 測るもの：構造の寿命、駆動を止めたときの崩壊時間。
- 位置づけ：ほぼ既達（対流の白 L3）。この段は「流れが止まれば秩序も止まる」という、以後の全段の前提確認として置く。
- 通過条件：役割 V（既知の対流物理と数で合う）。

### 段 L1：器の自己集合

- 問い：両親媒性の場（または phase-field ＋溶媒）とノイズだけから、閉じた袋（ベシクル）が勝手に生まれるか。
- 入れるもの：両親媒性分子の無理のない局所動力学、溶媒、一様＋ノイズの初期条件。
- 入れてはいけないもの：袋の形・大きさ・個数を初期条件やゲートに書くこと。
- 測るもの：閉じた膜の個数、サイズ分布、内と外の組成差（区画化の度合い）。
- 既知との一致（V の条件）：臨界濃度やサイズ分布が、脂肪酸ベシクルの実測・既知の自己集合物理と桁と傾向で合うこと。
- 既存資産：P15〜P19 の入れ物系譜、化学系の監査（PR #171・#172 系）。
- 天井の予告：受動的な系はここまで。次の段に進むには「成長」の供給が要る（e020 の負の結果：受動 phase-field は分裂しない＝役割 N の資産）。

### 段 L2：成長

- 問い：膜材料の供給（取り込み、または内部反応による生成）があるとき、袋の面積は持続的に増えるか。
- 入れるもの：L1 の系＋材料の濃度場と取り込みの局所規則。材料の出所は化学として明示する（P17「材料は中身が壊れた残り」の線も候補）。
- 測るもの：面積成長率、体積との比（A/V）の時間変化、内圧の代理量。
- 通過条件：成長が「置いた種の膨張」ではなく供給駆動であることを、供給を止める対照実験で示す（供給 OFF で成長が止まる）。

### 段 L3：分裂（形の不安定性として）

- 問い：成長した袋は、「割れる規則」なしに、形の不安定性としてくびれて分かれるか。
- 入れるもの：L2 の系のみ。分裂を指示する項は追加しない。
- 物理の見立て：体積の成長に表面の成長が追いつかない → 変形 → くびれ → 表面張力と内圧のバランス崩壊 → 分離。液滴のくびれ（レイリー型不安定性）と同族の通常物理として扱う。
- 測るもの：くびれ半径の時間変化、分離の有無、娘の個数とサイズ。ゲートは「割れたか」の二値でなく形の量で書く。
- 対照実験（必須）：成長なし条件では割れないこと（e020 型の負の対照が再現できること）。割れない条件で割れたら、埋め込みを疑い第8監査に戻る。
- 通過条件：役割 E（7＋8監査全通過）。パラメータを変えても出ること（監査6）。

### 段 L4：遺伝の入口（受け継がれる違い）

- 問い：娘袋の中身の組成は、親と相関しつつばらつくか（継承＋変異が同時にあるか）。
- 測るもの：親子の組成の相関、娘同士の差の分布、世代を重ねたときの差の持続。
- 位置づけ：RESEARCH_COMPASS の開いている問い4（「もともと内部状態を持つ白から、受け継がれる違い（遺伝）が育つか」）に直接つなぐ。
- 注意：この段の主張は「遺伝子」ではない。「違いが受け継がれる」という物理的事実の測定まで（tier：measured は測定値のみ、解釈は interpretive に分ける）。

### 段 L5：光の結合

- 問い：光を (a) エネルギーの流れ、(b) 膜内外の勾配の源、(c) 昼夜の周期強制、として結合すると、L1〜L4 のどの段がどう変わるか。
- 進め方：段ごとに1結合ずつ。最初は (c) 周期強制（濡れ乾き・温度サイクルに相当する境界条件の周期変化）が最も作為が少なく測りやすい。
- 主張の上限：この段の結果は当面 interpretive まで。established を名乗らない。

### はしご全体の天井（正直な見立て）

- L1〜L3 は既知物理の組み合わせで到達可能性が高い（年単位ではなく実験単位の話）。
- L4 は測定器の設計が本体。L5 と「代謝と遺伝が閉じて自己維持する系」は frontier。
- 全部つながった「原始生命が起きた」と言える日は、この設計書の範囲では約束しない。段ごとの E/V の蓄積が成果である。

## 第2部 ループしない自動研究の設計

### 0. 失敗の解剖（2026-08〜09 の bot 期、TREASURE_AUDIT より）

- 約7,000 run の実質は 37 条件の繰り返しだった。
- 原因は3つに分解できる：
  1. 提案生成が固定で、条件空間の同じ近所しか探らない。
  2. 成果を run 数で数え、新規情報の量を測っていなかった。
  3. 天井に到達したことを検出・申告する仕組みがなく、同じ白を回し続けた。
- 本設計はこの3点の裏返しである。過去の DREAM_LOOP 系文書は「記録」であり、本設計はそれらを運用根拠にしない。

### 1. 自動研究の規則（R1〜R8）

- **R1 問いへの紐付け義務**：すべての run は、開いている問い（羅針盤）か、明示した天井仮説のどちらかに紐づく。紐づかない run は実行しない。紐づけは run の記録に必須項目とする。
- **R2 条件指紋と重複禁止**：法則・パラメータ・初期条件・測定器の組を指紋（ハッシュ）化して試行台帳に残す。同型の指紋の再実行は事前に弾く（監査で事後に見つけるのではなく、実行前に止める）。
- **R3 成果は新規情報量で測る**：run の成果は「既存台帳から予測できなかった測定が得られたか」で数える。予測どおり＝情報量ゼロとして扱い、成功と呼ばない。
- **R4 天井カウンタと交代規則**：同じ白・同じ問いに対して新規情報ゼロが N 回（初期値 5、段ごとに調整可）続いたら、その白は「天井（仮）」として申告し、探索を別のはしご・別の白へ移すか、人間に上げる。同じ白の継続は人間の明示承認があるときだけ。
- **R5 役割分担**：AI は3役に分ける。
  - 提案者：仮説と条件を自由に発散させる（自由はここに最大限置く）。
  - 監査者：LAW の 7＋8 監査だけを見る。提案者と別モデルにする（例：Claude と GPT 系の分担）ことで盲点の共有を避ける。
  - 懐疑者：null 系・自明な系でもゲートが通ってしまわないか、埋め込みがないかを潰しにいく。
- **R6 ヒントカード制度**：光、経路和、黄金比、同期のようなヒントは、出典と claim tier を付けた「仮説カード」として登録し、探索の優先順位にだけ使う。カードは測るまで主張に昇格しない。ヒントは参考であり命令ではない、を機械的に担保するのがこの制度。
- **R7 人間の関所は2か所**：①北極星と、はしごの段の定義の変更、②役割 E/V（GREEN）の確定。この2つ以外は AI が自律で進めてよい。関所の判断材料（監査結果・反証・天井申告）は AI 側が揃えて上げる。
- **R8 停止と予算**：仮説カードごとに run 数と計算量の上限を持たせる。上限到達は失敗ではなく「この仮説はこの予算では届かなかった」という記録（役割 F/N の資産）として残す。

### 2. 実行形態（定期実行の置き方）

- 重い計算：開発側（Claude Code、CI、人＋AI のセッション）に置く。
- 軽い定期ループ：定期実行（例：1日1〜2回）で次だけを行う。
  1. 試行台帳と羅針盤を読み、現在の段・開いている問い・天井カウンタを把握する。
  2. 未実行の仮説カードから R1〜R4 に適合する次の一手を1つ選ぶ（または天井申告を起草する）。
  3. 監査役のチェックを通し、結果を台帳に追記する。
  4. **新しい発見・天井到達・人間の判断が必要な事項があるときだけ**、人に知らせる。何もない回は静かに終わる。
- 記録の置き場：試行台帳（指紋・問い ID・結果 tier・新規情報量）はリポジトリ内の research 配下を想定。羅針盤の更新は既存の生成手順に従う。

### 3. この設計が約束すること／しないこと

- 約束する：同じことの繰り返しは構造的に起きない（R2・R4）。自由な発散は監査と分離された場所で保たれる（R5・R6）。人が見ていない時間も、段の中の探索は前に進む。
- 約束しない：段が上がる速さ。誠実な天井申告は「進んでいない」のではなく、この研究の主成果の一つである。

## 付録A 定期実行の具体例：Dots への指示例（1時間ごと・複数並列）

第2部 §2「定期実行の置き方」を、開発側のエージェント実行環境（Dots）にそのまま渡せる指示例として書いたもの。並列数と天井カウンタの数字は仮置き（未決事項2・3に対応）。

```
Aeterna-Genesis の自律研究タスクとして、以下を1時間に1回実行してください。

【並列の構成】
- 毎回、独立した研究スレッドを3つ同時に回す。
- 各スレッドは開始前に「自分が担当する問い（羅針盤の開いている問い、または仮説カード）と対象の白」を宣言し、他のスレッドと対象が重ならないようにする。重なった場合は片方が別の対象に移る。

【各スレッドの1サイクル】
1. 試行台帳と RESEARCH_COMPASS を読み、現在の段・開いている問い・天井カウンタを把握する。
2. 自分の担当について、まだ試していない条件を1つ選ぶ。条件の指紋（法則・パラメータ・初期条件・測定器の組）が台帳にある既存のものと同型なら、その条件は選ばない。
3. 実験を1つ実行し、測定結果を台帳に追記する（指紋・紐づけた問い・結果の claim tier・新規情報があったかどうか）。
4. 監査（LAW の7＋8監査）の自己チェックを行い、埋め込み（第8監査抵触）の疑いがあれば、その結果は創発として扱わず記録に明記する。

【ループ防止】
- 「新規情報ゼロ」（既存台帳から予測できた結果）が同じ白・同じ問いで5回続いたら、その白は天井（仮）として申告し、その対象では新規 run を始めない。別の段・別の白へ移る。
- run の回数を成果として報告しない。成果は「新しく得た測定」と「天井の確定」だけ。

【やってはいけないこと】
- 北極星とはしごの段の定義を変更しない。役割 E/V（GREEN）の確定をしない（提案まで）。
- 同じ条件の再実行、結果に合わせた規則の調整。

【報告】
- 毎回の終わりに、3スレッド分をまとめて短く報告する：何を試し、何が新しく分かり、何が天井に近づいたか。
- 新規情報が何もなかった回は「新規情報なし」とだけ報告する。
```

調整の余地：①並列数（最初は3。監査の目が届く範囲で増減）、②天井カウンタの回数（仮に5）、③3スレッドのうち1つを監査・懐疑チェック専用にすると R5（提案・監査・懐疑の分離）に近づく。
